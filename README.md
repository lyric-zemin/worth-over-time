# 时间小票 · 陪伴账本

一款移动端优先的记账小应用：记下商品名称、价格和购买日期，它会自动配上有趣的图标，算出这件东西**已经陪了你多少天**、**平均每天花多少钱**。每次再打开，数字会从上次查看时的值滚动到今天的值——时间越久，小票越便宜。东西坏了、丢了或送人之后，还能给它盖上失效章，把那天的数字永久定格。

基于 Next.js 15 App Router + shadcn/ui + Tailwind CSS，纯前端、无账号、无服务器，可直接用 GitHub Actions 发布到 GitHub Pages。

## 本地运行

需要 Node.js 20 及以上。

```powershell
npm install
npm run dev
```

打开 <http://localhost:3000>。其他命令：

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 常规生产构建 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm run dev` | 本地开发 |

## 功能说明

- **记一笔**：名称、金额（精确到分）、购买日期；名称自动匹配离线图标规则，可手动更换，也可上传本机图片（自动裁方、压缩后存在本地）。
- **时间小票**：`已购天数 = 日历天数差 + 1`（购买当天算第 1 天），`日均成本 = 四舍五入(价格分 / 已购天数)`。所有金额以整数「分」存储和运算，不会出现浮点误差。
- **失效与定格**：详见下一节。盖章后天数与日均成本写入记录并固化，不再随日期变化。
- **上次查看的变化**：应用会保存上次查看时的快照。再次打开时展示隔了几天、天数增加了多少、每天成本便宜了多少，并用滚动数字从旧值过渡到新值。只统计有效小票；期间新增的记录仅计入统计。首次打开只建立基线，同一天重复打开提示「与上次一致」。
- **回顾**：累计陪伴天数、日均成本排行与分类占比，只算有效小票。
- **外观**：浅色 / 深色 / 跟随系统，外加暖橘、暮紫、薄荷、麦芽四套配色。
- **数据**：全部保存在当前浏览器的 `localStorage`。支持 JSON 全量备份（含图标图片、外观偏好与失效记录）、CSV 表格导出，以及「合并追加 / 覆盖恢复」两种导入方式。清空数据前有二次确认。
- **交互**：撕边小票与日戳质感、上滑抽屉、侧滑撕下并可撤销、盖章动效、轻震动反馈，支持系统的「减弱动效」偏好。

> 换浏览器、换设备或清理浏览器数据前，记得先导出 JSON 备份。

## 失效与定格

在有效小票的详情里点「标记失效」：

1. **失效日期**：默认今天，可回溯到「购买日 ~ 今天」之间的任意一天，日历会自动挡住范围外的日期。
2. **失效原因**：必填，提供「坏了 / 丢了 / 卖掉 / 退掉 / 送人」快捷标签，填入后仍可继续编辑（最多 60 字）。
3. **盖章瞬间计算并写入**：`共陪伴天数 = 失效日 - 购买日 + 1`，`定格日均 = 四舍五入(价格分 / 共陪伴天数)`。预览卡会随日期弹性更新，确认后这两个数字被固化在记录里，之后刷新、跨天、导出导入都不再变化。操作时间也会记下，界面显示到分钟。

失效之后：

- 这张小票从**总投入、每天合计、件数、回顾页排行与分类占比、上次查看的变化动画**中剔除；小票墙主列表只显示有效小票。
- 它收进小票墙下方的「已失效 · 归档」区，区内保持当前排序；纸面褪色、图标去饱和、斜盖「已失效」印章并带一次落下动画，卡片上直接显示原因、失效时间、共陪伴天数与定格日均，数字静止不再滚动。
- 归档区可一键收起 / 展开，「我的」设置页也有同一个开关，偏好会记住。
- 详情里可**一键恢复有效**：清空失效信息，重新按原购买日期计算天数与日均成本。误标可撤销，撕下归档小票后撤销也会带回失效状态。

数据兼容：失效原因是文字、`expiredOn` 是日历日、`expiredAt` 是操作时间戳，定格值与它们一起随 JSON 备份导出。之前导出的 JSON 备份和本机旧数据缺少这些字段时，会自动按有效小票处理，照常打开。CSV 是**查阅型**表格：导出全部小票并追加「状态 / 失效日期 / 失效原因 / 记录时间」等列；导入时只按「商品名称 / 价格 / 购买日期」构造有效小票（已失效行会跳过），完整恢复请用 JSON。

## 用 GitHub Actions 发布到 GitHub Pages

1. 在 GitHub 新建一个仓库（例如 `worth-over-time`），把本项目推上去，分支用 `main` 或 `master` 都可以。
2. 打开仓库 **Settings → Pages**，把 **Build and deployment → Source** 设为 **GitHub Actions**（首次发布必须做这一步）。
3. 推送代码，或在 **Actions** 里手动运行「部署到 GitHub Pages」工作流。
4. 完成后访问 `https://<用户名>.github.io/<仓库名>/`。

工作流会自动从仓库名推导 `basePath`：

- 项目站点（如 `worth-over-time`）→ 构建时注入 `NEXT_PUBLIC_BASE_PATH=/worth-over-time`；
- 用户站点（仓库名是 `<用户名>.github.io`）→ 自动使用根路径。

因此**不需要**为了改仓库名去修改 `deploy.yml`。工作流还会在产物中写入 `.nojekyll`，避免 `_next` 目录下的 JS/CSS 被 Jekyll 忽略而 404。

想在本机复现静态产物（PowerShell）：

```powershell
$env:STATIC_EXPORT = "true"
$env:NEXT_PUBLIC_BASE_PATH = "/worth-over-time"
npm run build
# 产物在 out/，用任意静态服务器托管 out 目录即可，注意带 /worth-over-time 前缀
Remove-Item Env:STATIC_EXPORT
Remove-Item Env:NEXT_PUBLIC_BASE_PATH
```

## 目录速览

```
src/app          页面入口、全局样式、manifest 与图标
src/components   UI 组件：小票、归档区、失效/详情抽屉、变化横幅、洞察、设置
src/components/ui shadcn/ui 基础组件（new-york / stone / CSS 变量）
src/lib          金额、日期、失效固化、排序、图标规则、图片压缩、快照、导入导出、本地存储
src/store        zustand 持久化状态（skipHydration + 客户端显式 rehydrate）
src/types        共享数据类型
.github/workflows GitHub Pages 部署工作流
```
